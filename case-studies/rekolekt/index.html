Rekolekt + HasanAra

From long recordings to timestamped passages

A long recording becomes useful reference material when a reader can find a phrase and return to the moment it was spoken. Rekolekt supplies the processing and API; HasanAra gives that system a concrete archive and reader experience.

Keep the source attached to the answer

Ingestion and transcription are expensive, interruptible jobs. Search needs to stay useful while processing continues, and a transcript result needs to preserve its recording and timestamp so a person can inspect the source.

I built the headless Rekolekt backend and HasanAra’s independent React frontend. The rekolekt-web package supplies generated API types, hooks and reusable player/transcript behavior; the archive owns its pages and identity. These are parts of one system rather than three unrelated portfolio projects.

Make completion depend on ownership

Workers claim durable attempts, renew leases and record their progress. Finalization uses the attempt’s identity and ownership, so a worker finishing after interruption cannot simply overwrite the result of a newer attempt.

Network and GPU work runs outside the database transaction. Short database operations claim and finalize work; the application does not hold a transaction open for an entire download or transcription.

The tradeoff. Lease expiry, cancellation and retries create more states than a simple in-memory queue. They are also the states an operator needs to recover work deliberately.

Keep the primary store authoritative

PostgreSQL owns archive records. Optional OpenSearch acceleration is fed through a transactional outbox, with versioned updates and deletion tombstones. The API exposes indexing freshness so a reader or operator can distinguish an empty answer from a stale index.

Classified search outages can fall back to PostgreSQL. That fallback is a defined degraded mode, not a reason to hide authorization, validation or quota errors. The outbox tests exercise update and deletion behavior at the database boundary.

The tradeoff. A second search backend carries synchronization and recovery costs. A source-of-truth store, explicit lag metadata and a bounded fallback make those costs observable.

Finish at the recording

HasanAra groups search results by broadcast and offers the matching moment, a shareable passage and the full recording. The new search screenshot uses a real public query and retains the visible transcript context.

Machine transcription can be wrong, and a passage link can change when its source or transcript changes. The archive asks readers to check the recording before quoting. This study does not describe passage links as immutable citations.

Evidence and limits

Transcripts are machine-generated and archive coverage is incomplete. Screenshots record a dated view of the public archive, not transcription accuracy or a new processing-performance benchmark.
