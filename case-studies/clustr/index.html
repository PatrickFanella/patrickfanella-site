Clustr

From Reddit activity to an explorable graph

Clustr turns Reddit activity into a map of communities and the relationships between them. The interesting engineering problem is keeping collection, graph construction and exploration coherent while the underlying data keeps changing.

A graph needs a collection policy

Collecting external data is bounded by API quotas, network failures and the cost of revisiting existing records. A map also needs a defined interpretation: links represent observed relationships, not a complete or permanent account of a community.

I built the Go collection and publication pipeline and its browser explorer. The public application offers a 3D universe, a 2D map, data views and linked entity inspection. A separate Unity client consumes the same API and remains a prototype.

Make interrupted collection recoverable

A durable crawl request is separate from a particular worker attempt. The lifecycle code records a worker identity, lease and attempt outcome, and distinguishes complete, partial, retryable, permanent-failure and cancelled work.

An explicit request can bring an existing community forward for another crawl. A historical successful job therefore does not become a permanent marker that prevents the data from ever being refreshed.

The tradeoff. Leases and retries add state to operate and test. They also make unfinished work visible instead of hiding it in a worker process that may disappear.

Publish a world rather than a work in progress

Graph generation and publication are separate from the crawler. The publication path bounds node and link counts, constructs the required artifacts, then commits those artifacts and the current revision pointer atomically.

The weighted Louvain boundary sorts source identities and edges and uses an explicit random seed. Repeated builds can therefore reproduce the partition for the same inputs and parameters, which makes graph changes easier to investigate.

The tradeoff. A published revision is a consistent snapshot, so it deliberately trails collection. Caps keep resource use bounded but also define what the explorer can show.

Let readers follow the same revision

The explorer and API expose views of the published world rather than querying every crawler table directly. The revision integration test checks that publication refuses an absent or unpublished spatial catalog without moving the current pointer.

The screenshots show the actual public application captured on November 16, 2026. Rendering and dataset coverage have their own limits; a graph image does not establish collection completeness or a benchmark for large-world performance.
