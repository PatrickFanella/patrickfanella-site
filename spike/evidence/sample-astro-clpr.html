Clpr

A Twitch clip discovery app with creator and topic search, playlists, and moderation. I built and operate the Go API, React client, and search pipeline.

Open it Source

The problem

A Twitch clip is easy to make and hard to find a week later. Viewers had no dependable place to vote on clips, organize them, talk about them, or search for one they half remember.

What I built

Clpr helps viewers find Twitch clips by creator, topic, and tag, then save and share them in playlists. I built the Go API, React web client, PostgreSQL model, moderation tools, and hybrid search pipeline, and handle container releases and public-service operations.

  • Built clip discovery, playlists, voting, discussions, and moderation around one Go API and responsive React client.
  • Designed hybrid lexical and semantic retrieval so exact clip metadata and conversational queries can use different relevance signals.
  • Operate the public clpr.tv deployment from a tested, tagged release with documented verification and rollback paths.

How it's built

The React client uses a versioned Go API for discovery, accounts, playlists, and moderation. PostgreSQL owns the durable data; client behavior stays separate from retrieval and background processing.

Clip titles and tags benefit from exact matching, while conversational queries need semantic retrieval. I combined BM25 and vector search so each path can be evaluated and fail independently.

PostgreSQL remains the system of record, while Redis handles sessions and caching and OpenSearch serves retrieval. Keeping those responsibilities separate improves recovery, at the cost of explicit synchronization and health checks.

What I learned
  • A hybrid search stack adds operational cost, so its lexical and semantic paths need independent failure handling and measurable relevance tests.
  • A versioned API keeps interface changes separate from retrieval and moderation behavior, but requires explicit contract checks.
