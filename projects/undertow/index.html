Undertow

A layered music-video editor with timed lyrics and local MP4/WebM export, built around a browser rendering and encoding pipeline.

Status
Public editor; optional cloud features in testing
Role
Full-stack engineer
Period
2026–present
Read the case study Visit Undertow Repository

Product and scope

I built the browser editor and local rendering pipeline. A project combines audio-reactive visuals, artwork and timed lyrics, with separate layouts for landscape, portrait and square exports. Local editing and rendering work without an account.

Stack
React, TypeScript, Web Audio, WebCodecs, Canvas, MediaBunny

The problem

A musician needs a finished video as well as a convincing preview. Browser codecs, frame timing and large output files make the export path as important as the editor.

What I built

  • Built layered visual composition, audio analysis and timed lyric controls.
  • Built per-format layouts, project persistence and local video export.
  • Added chunked output handling and an end-to-end browser export self-test.

How it fits together

The compositor draws each output frame and hands it to the browser encoder through MediaBunny. Codec negotiation follows the browser’s actual capabilities.

Seekable Blob chunks let the muxer patch file headers without allocating one file-sized ArrayBuffer. The export loop yields to the browser to keep the interface responsive.

What I learned

  • A successful preview does not prove export works. Container bytes, codec support, frame timing and memory require their own checks.
  • Encoding limits belong in the interface: some browsers cannot produce audio, and hardware support varies.
