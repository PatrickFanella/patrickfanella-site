Product and scope

PatrickFanella.co runs this portfolio through a React frontend, Go API, and PostgreSQL content model. The repository includes migrations, seed data, a generated sitemap, and deployment documentation.

Stack
Go, React, TypeScript, PostgreSQL, Docker, Vite, SEO

The problem

A portfolio could be a handful of static pages. I wanted the project data validated and reusable, so it got a schema, a seed file and a deployment path. That is more machinery than a portfolio strictly needs.

What I built

  • Built the public React interface and Go API around a PostgreSQL portfolio model.
  • Added migrations and seed validation so content changes follow the database schema.
  • Generated the sitemap from project content and documented the deployment path.

How it fits together

The React app reads portfolio data through a Go REST API.

PostgreSQL stores project records, with migrations and seed data defining content changes.

Docker supports local services and deployment, while prerendering supplies public pages and SEO metadata.

What I learned

  • Keeping portfolio content in a schema catches missing fields and broken relationships before deployment.
  • Sitemap and prerender checks need to read the same records as the UI or public metadata will drift.
