Augr

A trading system in active development. Agents analyze, argue the bull and bear cases and review risk before any order is placed, and a paper-trading mode tests the whole path without risking capital.

Status
Active development
Role
Systems/product engineer

Product and scope

Augr moves a trade through parallel analysis, bull and bear debate, signal generation, risk debate, and execution. Its Go backend connects multiple model providers, market-data feeds, and broker adapters. Operators can use a Cobra CLI, Bubble Tea TUI, REST API, WebSocket stream, or React dashboard. Paper trading tests the workflow against market data without risking capital.

Stack
Go, React, TypeScript, PostgreSQL, Redis, WebSocket, Bubble Tea, AI Agents

The problem

A generated trade signal should not reach a broker before opposing analysis and risk review. The same pipeline also needs a paper-trading path for testing without capital risk.

What I built

  • Built a five-phase pipeline where analysts debate bull and bear cases and risk across multiple rounds before producing execution signals.
  • Built broker adapters for Alpaca and Binance with paper-trading modes, enabling full pipeline testing against real market data without capital risk.
  • Integrated six LLM providers and four market data sources behind unified interfaces, allowing runtime provider switching without pipeline changes.

How it fits together

A Go 1.25 backend runs five phases in order: parallel analysis, a three-round research debate, a trading signal, a three-round risk debate, and execution. Each phase emits structured output for the next.

One LLM interface covers OpenAI, Anthropic, Google, OpenRouter, XAI and Ollama. One market-data interface covers Alpha Vantage, Polygon, Yahoo Finance and Binance.

Operators get a Cobra CLI and a Bubble Tea TUI. A chi/v5 REST API with WebSocket streaming feeds the React and Vite dashboard, PostgreSQL 17 keeps state, and Redis 7 caches.

What I learned

  • Giving agents opposing mandates (bull against bear, aggressive against conservative) and several rounds surfaced objections that a single-pass analysis did not raise.
  • A paper-trading adapter is only useful if it simulates latency, partial fills and slippage. A mock that always fills instantly makes a strategy look better than it is.
