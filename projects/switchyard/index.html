Switchyard

An automation runtime in active development. It routes workflow state between services and shows operators where each piece of work is.

Status
Active development
Role
Automation engineer
Period
2026–present

Product and scope

Switchyard is an active-development automation runtime. Its Go backend routes workflow state, while a Vite, React, and TypeScript interface lets operators inspect work and service handoffs. The Dockerized monorepo provides the current foundation for adding workflow modules.

Stack
Go, React, TypeScript, Docker, Workflow Engine, Automation

The problem

Background automation is difficult to operate when queues and handoffs appear only in logs. Operators need to inspect routed work and its current state.

What I built

  • Built a full-stack automation runtime foundation with Go services and a Vite React operator interface.
  • Added Make and Docker workflows for running the Go and React services together.
  • Focused the product around visible workflow routing instead of opaque background scripts.

How it fits together

Go backend exposes workflow and runtime primitives while the React frontend provides an operator-facing control surface.

Docker Compose and Make targets run local development and tests across the backend and frontend.

Runtime model treats automation as routed work with inspectable state, making failures and handoffs easier to reason about.

What I learned

  • When queues, decisions and handoff state are on screen, a failed handoff is something an operator can find. In log-only automation it is something they reconstruct.
