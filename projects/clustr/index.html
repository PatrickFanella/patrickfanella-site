Clustr

A Reddit community explorer connecting a durable Go crawler, reproducible graph builds and an interactive 2D/3D map.

Status
Public application; active development
Role
Backend and full-stack engineer
Period
2026–present
Read the case study Visit Clustr Repository

Product and scope

I built Clustr’s data collection, graph publication and browser explorer. Reddit activity becomes a weighted map of communities, with search, shareable views and a revision-aware API for the web app and a separate Unity prototype.

Stack
Go, PostgreSQL, React, TypeScript, WebGL

The problem

External data changes while people explore it. A useful community map needs bounded collection, recoverable work and a consistent published graph.

What I built

  • Built a crawler with global rate limits, durable requests, worker leases and retry outcomes.
  • Built weighted graph construction and reproducible community partitioning.
  • Published immutable graph revisions for 2D/3D exploration, search and linked entity views.

How it fits together

A Go crawler writes normalized PostgreSQL records. A separate build stage constructs communities and spatial data before publishing a complete revision.

Publication commits the graph artifacts and current pointer atomically. Stable ordering and an explicit seed make the weighted Louvain partition reproducible.

What I learned

  • Data collection and publication have different failure boundaries. A partial crawl should not become a half-published world.
  • Graph caps and rendering detail are engineering budgets, not claims about the size of the live dataset.
