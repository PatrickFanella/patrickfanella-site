Subcorp

A self-hosted platform where six named agents propose, debate, and run missions through real-time chat and sandboxed tools.

Product and scope

Six named agents use Subcorp to propose work, debate approaches, run missions, and talk through the real-time Sanctum interface. Each agent has a distinct identity and access boundary. The app combines Next.js, React, PostgreSQL with pgvector, WebSockets, queued workflows, and a sandbox for bash, file I/O, web search, and memory retrieval.

Stack
Next.js, React, TypeScript, PostgreSQL, pgvector, WebSocket, Docker, AI Agents

The problem

Six agents sharing tools and a chat room need clear identities, ordered messages, and strict access boundaries. Without them, simultaneous actions conflict and tool access becomes unsafe.

What I built

  • Deployed a live system where six agents propose, debate, and run missions with limited human intervention.
  • Built a real-time Sanctum chat interface with WebSocket-driven @mention routing, whisper channels, and structured roundtable conversation modes.
  • Designed a sandboxed toolbox container giving agents access to bash, Python, Node.js, web search, file I/O, and semantic memory, isolated from the host system.

How it fits together

The app is Next.js 16 and React 19. PostgreSQL 16 with pgvector holds 45 tables, including the agents' semantic memory, and the OpenRouter SDK handles model calls.

A WebSocket layer carries agent-to-agent and agent-to-user messages, with structured routing, @mention parsing and private whispers.

Agents run bash, Python and Node.js, search the web and read and write files inside a Docker container that is network-isolated from the host and resource-limited.

What I learned

  • The same model behaves very differently once it has a distinct identity, relationships with the other agents and its own tool permissions. Those settings mattered as much as which model I picked.
  • Ordering messages between six agents was the hard part. Race conditions between agents proposing actions at the same moment were the hardest bugs I had to debug.
