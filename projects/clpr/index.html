Clpr

A Twitch clip discovery product with creator and topic search, curated collections, playlists and moderation.

Status
Public application
Role
Full-stack engineer
Period
2025–present
Read the case study Read the search decisions study Visit Clpr Repository

Product and scope

I build and operate the Go API, React client and search pipeline behind Clpr. The public product connects clip discovery to collections and playlists, with creator workflows and a moderation process around submissions, reports and appeals.

Stack
Go, React, TypeScript, PostgreSQL, Redis, OpenSearch

The problem

A clip is easy to make and difficult to find again. Discovery needs useful search and browsing, while submissions and shared collections need clear account and moderation boundaries.

What I built

  • Built creator, topic and tag discovery, clip search and shareable playlists.
  • Connected the React interface to versioned Go APIs, persistence and background processing.
  • Built submission review, reports, appeals and audit trails.

How it fits together

PostgreSQL is the durable store. The Go search repository converts a request into separate result sets for clips, creators, games and tags; Redis and optional search services have distinct responsibilities.

The current product includes speech-transcript filtering. The portfolio Desk separately runs an older, explicitly pinned PostgreSQL search path against labelled fixtures.

What I learned

  • A search explanation needs its exact query, source version and data context. A fixture benchmark is useful evidence about an implementation, not production traffic.
  • A product feature is only part of the supported scope when the active routes and release contract agree.
