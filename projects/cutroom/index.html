Cutroom

A short-form video production system where specialized agents claim stages in a seven-step workflow from research through publishing.

Status
Status not stated in source
Role
Full-stack product engineer

Visit Cutroom

Product and scope

Cutroom moves a short video through seven stages from research to publishing. A specialized agent can claim each stage, and every handoff uses structured output. The Next.js 14 and React 18 dashboard connects to Prisma and PostgreSQL, Remotion rendering, ElevenLabs voice generation, Pexels visuals, and attribution on Base. The hosted app includes templates, pipeline views, and examples.

Stack
Next.js, React, TypeScript, Prisma, PostgreSQL, Remotion, AI Agents, ElevenLabs

The problem

Research, scripting, voice, visuals, editing, and publishing produce different artifacts. Cutroom gives each stage a defined handoff so the next worker does not have to reconstruct earlier decisions.

What I built

  • Built a seven-stage production pipeline that turns a topic into a short-form video through structured handoffs.
  • Shipped a template-driven creative system with real-time pipeline tracking, attribution weights, and token-based reward logic for contributors.
  • Integrated Remotion rendering, ElevenLabs voice synthesis, and multi-platform publishing workflows behind a single hosted dashboard.

How it fits together

Next.js 14 app-router frontend and API surface share a TypeScript codebase, with dashboard pages, REST endpoints, and pipeline orchestration living in the same application boundary.

Prisma-backed PostgreSQL persistence stores pipelines, stages, and attribution metadata while Remotion assembles the final video output from structured stage artifacts.

External integrations connect voice generation, visual sourcing, and Base token distribution so the production flow can move from topic intake to published asset without ad hoc handoff glue.

What I learned

  • Handoff structure mattered more than model quality here: the clearer the schema between stages, the less rework the editing stage had to absorb.
  • Attribution changes the data model because every stage must retain its contributor and weight. Adding it after rendering would lose that history.
