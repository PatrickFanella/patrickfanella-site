Subcult OS

An event-operations app for planning, staffing, free reservations, door check-in, and close-out reports. I built the Go API, React web app, and mobile workflows.

Status
Alpha development
Role
Lead full-stack engineer
Period
2026–present
Visit Subcult OS Repository

Product and scope

Subcult OS keeps event plans, crew roles, reservations, door check-in, and private closing reports in one workspace. The React web app handles planning and discovery, while an Expo mobile client supports event-time scanning and staff views. The alpha lifecycle has been exercised with rehearsal data. Public delivery currently covers free reservations.

Stack
Go, React, TypeScript, PostgreSQL, Docker, TailwindCSS, Expo, React Native

The problem

Live event work is split across spreadsheets, ticketing systems, staff rosters and cash records. I am building Subcult OS to keep admissions, incidents, shifts, settlements and closing reports in the same system.

What I built

  • Built event workflows covering free ticket reservations, door check-in and guest lists.
  • Created operational modules for staff shift scheduling, security incident logging, and automated vendor payout calculations.
  • Designed financial tracking and night-close reports for door revenue, bar cuts, and vendor disbursements.

How it fits together

The Go API and PostgreSQL model own workspace permissions, reservation state, and check-in transitions.

The React web app handles planning and discovery; the Expo/React Native client carries scanning, door search, and event-time views.

Closing reports retain the source records for admissions and event activity so discrepancies can be investigated.

What I learned

  • On the night, the door screen has to be fast and has to survive bad venue connectivity. A multi-step flow loses to that every time.
  • Night-close reports need source records for admissions, receipts, and staff hours so discrepancies can be traced.
