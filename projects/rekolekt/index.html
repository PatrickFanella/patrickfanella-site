Rekolekt + HasanAra

A reusable recording-archive backend and its public HasanAra application, connecting long-running ingestion to timestamped transcript search.

Status
Backend in use; public archive
Role
Design and engineering
Period
Active in 2026
Read the case study Visit Rekolekt + HasanAra Repository

Product and scope

I built Rekolekt’s ingestion, transcription, search and API, and HasanAra’s independently branded React frontend. Rekolekt is the headless engine; rekolekt-web supplies typed clients and reusable behavior; HasanAra is the public broadcast archive.

Stack
Python, FastAPI, PostgreSQL, Redis, Whisper, React, TypeScript

The problem

Hours of recordings are hard to search and cite. Expensive processing must recover from interruptions, and a result must retain the original recording and timestamp.

What I built

  • Built durable ingestion and transcription jobs with retries, cancellation and worker leases.
  • Built passage links, timestamped transcripts and source-aware search.
  • Separated the backend contract, shared frontend kit and HasanAra application.

How it fits together

FastAPI serves the stable API, PostgreSQL owns the records, and background workers perform network and transcription work outside database transactions.

Optional OpenSearch acceleration is maintained through a transactional outbox. Classified outages fall back to PostgreSQL while exposing freshness and degraded-state metadata.

What I learned

  • A worker completing late must not overwrite a newer attempt; ownership and finalization need explicit database checks.
  • Machine transcripts can be wrong. A searchable passage should lead back to the recording, with that uncertainty visible.
