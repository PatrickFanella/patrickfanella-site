Arkhiv

A shared archive engine for print, audio and video, with source provenance, reviewed access and independently deployed collection frontends.

Status
Shared engine; consumer releases qualified separately
Role
Lead engineer
Period
2026–present
Visit Arkhiv Repository

Product and scope

I built the archive engine and its release contracts. Branded consumers own their interfaces while sharing catalog, search, media identities and reviewed access decisions. Anarchist Archive, Riot Grrrl, Lineage and the replay-channel apps belong to this family.

Stack
Go, PostgreSQL, TypeScript, Docker

The problem

Sharing backend behavior should not erase a collection’s identity or silently change its access rules.

What I built

  • Built source metadata, editorial history and media/access boundaries.
  • Added immutable engine pins, additive migrations and explicit consumer compatibility contracts.

How it fits together

Each consumer upgrades its pinned headless engine through a reviewed change. Metadata retention is independent of acquisition and public playback permission.

What I learned

  • A successful core release does not qualify every consumer. Each branded application needs its own upgrade and recovery evidence.
